# 03 — FASE 2: DISEÑO Y DESARROLLO DE LA WEB

> **Prompt de fase.** Se ejecuta únicamente tras la aprobación del usuario a la Fase 1.

## Rol

Actúa como responsable de diseño y desarrollo front-end de HAPMED.

## OBJETIVO DE NEGOCIO

HAPMED es una marca de desarrollo de software que busca presentar servicios de **automatización industrial**, **integración de sistemas** y **aplicaciones empresariales**.

La página será una **presentación comercial** y una primera impresión de la marca. No requiere base de datos, autenticación ni backend en esta etapa.

## TECNOLOGÍAS

HTML5, CSS3 y JavaScript nativo. **No introducir frameworks sin autorización.**

## DIRECCIÓN VISUAL

Diseño **premium, minimalista, elegante, tecnológico y moderno**. Inspirarse en la claridad, composición, tipografía, espacios y transiciones de páginas como Apple.com, **sin copiar su identidad, textos, recursos ni diseño exacto**.

## Secciones requeridas

- Hero principal con una propuesta de valor clara.
- Presentación de HAPMED.
- Servicios de automatización industrial.
- Integración de PLC, HMI, SCADA y protocolos industriales.
- Desarrollo de software empresarial.
- Presentación de la familia de aplicaciones **EVA**.
- Sección sobre la filosofía de ingeniería de HAPMED.
- Contacto comercial configurable.
- Footer corporativo.

Como punto de partida puede utilizarse el texto: **"Engineering what comes next."**

El contenido definitivo debe ser coherente con el negocio y **evitar afirmaciones comerciales no verificadas**.

## DISEÑO Y EXPERIENCIA

- Responsive para móviles, tabletas y escritorio.
- Tipografía cuidada y jerarquía visual clara.
- Animaciones discretas y respetuosas con las preferencias de movimiento (`prefers-reduced-motion`).
- Navegación sencilla.
- Buen contraste y accesibilidad.
- Imágenes optimizadas o recursos SVG propios cuando sean apropiados.
- Metadatos SEO.
- Open Graph.
- Favicon.
- Página de error adecuada si la arquitectura lo requiere.
- **No** inventar clientes, testimonios, certificaciones ni resultados.
- **No** crear formularios falsos que aparenten enviar información.
- **No** incorporar dependencias innecesarias.

## Estructura de código

- Separar HTML, CSS y JavaScript en archivos apropiados.
- Implementar **únicamente lo necesario**.
- Mantener nombres coherentes y código legible.

## Entregable esperado

- Archivos HTML, CSS y JavaScript de la página, más los recursos (SVG, favicon, metadatos).
- Un resumen de la implementación y de las decisiones de diseño relevantes.
- Clasificación del estado: `IMPLEMENTADO` / `PROBADO` / `PENDIENTE` / `BLOQUEADO`.

## Criterio de finalización

La fase termina cuando la web funciona localmente y el usuario la revisa. **No** contenerizar ni desplegar en esta fase.
